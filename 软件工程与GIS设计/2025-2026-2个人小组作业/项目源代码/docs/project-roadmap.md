# StarRunning 项目推进总方案

## 当前基线

当前项目已经进入 MVP 联调阶段，核心链路是:

1. 微信小程序原生地图页加载校园数据。
2. 获取定位并记录轨迹点。
3. 根据轨迹点亮 5m 逻辑网格。
4. 触发 POI、quiz、路线和成就。
5. 结束探索后进入结算页。
6. 通过 `sdkpFunctions` 同步用户汇总、网格、POI 和探索会话到微信云开发。

当前优先目标不是继续扩展玩法，而是先让这条链路在开发者工具和真机中稳定可验收。

截至 2026-05-16，结算页、历史页和 POI 图鉴页已经落地；本阶段重点是验收稳定化和测试护栏，不再把这些页面列为待开发主任务。

## 阶段一：运行闭环稳定

目标:

- 消除微信开发者工具运行错误。
- 云函数部署后能正常同步。
- 真机定位流程可跑通。

已完成:

- 修复定位隐私接口声明。
- 修复单点轨迹 `polyline` 报错。
- 修复云数据库 `_id` 写入错误。
- 增加云调用失败日志。
- 增加微信开发者工具调试文档。
- 增加探索结算页、历史探索记录页和 POI 图鉴页。
- 增加页面展示模型测试和云函数 handler mock 测试。

验收标准:

- `npm test` 通过。
- `npm run check:js` 通过。
- 首页 `立即同步` 不报错。
- 云数据库出现 `userinfo`、`gridstatus`、`poi_records`、`track_sessions`。
- 至少一次 `授权定位 -> 开始探索 -> 点亮网格 -> 发现 POI/quiz -> 结束探索 -> 结算页 -> 云端写入 -> 重新打开恢复进度` 完成。

## 阶段二：后端内部模块化

目标:

- 保留 `sdkpFunctions` 单入口。
- 不改变前端 `wx.cloud.callFunction` 调用协议。
- 将云函数内部拆成清晰模块，降低后续增加配置读取、历史记录和排行榜时的改动成本。

任务:

- 拆出云开发上下文和集合初始化。
- 拆出 `profile`、`grid`、`poi`、`session` handler。
- 保留 `index.js` 作为事件分发入口。
- 更新本地 JS 检查脚本覆盖新增云函数模块。

验收标准:

- 云函数部署后所有原有事件仍可用。
- `syncExploreSummary`、`syncGridStatus`、`syncPoiRecords`、`syncExploreSession` 行为不变。
- `npm test` 和 `npm run check:js` 通过。

## 阶段三：云端配置读取

目标:

- 逐步把 POI、quiz、路线、成就配置从本地静态文件迁移到云端可配置来源。
- 前端先支持“云端配置优先，本地配置兜底”。

任务:

- 新增配置读取事件，例如 `getRuntimeConfig`。
- 设计 `runtime_config`、`poi_config`、`route_config`、`achievement_config` 集合结构。
- 前端增加配置缓存和版本字段。

验收标准:

- 无云端配置时仍使用本地配置。
- 有云端配置时可覆盖 quiz 题目和 POI 文案。

## 阶段四：真机定位与体验修正

目标:

- 解决模拟器和真机定位表现差异。
- 校准 POI 半径、GPS 弱信号提示、后台定位提示。

任务:

- 真机测试定位授权、连续定位、后台定位。
- 记录不同机型 GPS 精度。
- 调整弱信号阈值、轨迹采样频率和 POI 触发半径。

验收标准:

- 校园内实际行走能稳定点亮网格。
- 误触发 POI 明显减少。
- 结束探索结算数据合理。

## 阶段五：功能扩展

目标:

- 在稳定 MVP 之上扩展用户可感知功能。

候选任务:

- 成就页。
- 独立 POI quiz 页面。
- 更丰富的历史探索详情和 POI 图鉴筛选。
- 排行榜。
- 社交比较和周报。

优先级:

先完成真机验收和云端同步稳定化，再考虑独立 quiz、成就页、排行榜和社交玩法。
