# 师大快跑数据库元数据说明文档

## 1. 文档基本信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 师大快跑：点亮校园计划 |
| 项目类型 | 基于 GIS 与游戏化设计的校园空间探索微信小程序 |
| 数据库平台 | 微信云开发 / CloudBase 云数据库 |

本项目面向福建师范大学旗山校区在校生，目标是通过微信小程序记录用户在校园中的步行或跑步行为，并利用 GIS 空间分析思想将真实移动轨迹转化为地图点亮、地标触发、探索进度统计等轻游戏化反馈。当前数据库主要服务 MVP 阶段的核心闭环：用户进入小程序后开始探索，系统记录探索会话、更新网格点亮结果、保存用户探索总进度，并在到达 POI 地标时生成触发记录。

## 3. 数据库设计概述

当前数据库采用 NoSQL 文档型结构，每个集合对应一个相对独立的业务对象。集合之间通过用户标识 `user_id`、探索会话标识 `session_id`、网格标识 `grid_id` 和 POI 标识 `poi_id` 进行逻辑关联。

| 集合名称 | 中文名称 | 主要用途 | 记录粒度 |
| --- | --- | --- | --- |
| userinfo | 用户信息 | 保存用户基础信息和累计探索进度 | 每个用户 1 条 |
| track_sessions | 探索会话记录 | 保存一次开始探索到结束探索的过程统计 | 每次探索 1 条 |
| gridstatus | 网格点亮进度 | 保存用户点亮的具体校园网格 | 每个用户-网格组合 1 条 |
| poi_records | POI 点亮记录 | 保存用户触发过的校园地标或兴趣点 | 每个用户-POI 组合 1 条 |

## 4. 集合元数据说明

### 4.1 userinfo 用户信息集合

`userinfo` 用于记录用户基础身份与总体探索结果，是其他集合按用户聚合统计的基础。

| 字段名 | 数据类型 | 是否核心字段 | 字段含义 |
| --- | --- | --- | --- |
| _id | String | 是 | 用户记录主键，当前使用微信用户 OpenID |
| nick_name | String | 否 | 用户昵称；当前样例中可为空，后续可由用户授权或自定义填写 |
| total_grids | Number | 是 | 用户累计点亮的网格数量 |
| explore_ratio | Number | 是 | 用户累计探索比例，用于主界面进度展示 |
| updated_at | Date | 是 | 用户探索统计最后更新时间 |

主键规则：`_id = 用户唯一标识`。  
更新方式：当用户完成探索、点亮网格或探索比例发生变化时更新。  
业务作用：为个人页、探索进度看板、排行榜等功能提供基础统计数据。

### 4.2 track_sessions 探索会话记录集合

`track_sessions` 用于记录用户一次探索过程的摘要信息，便于回溯每次探索的时长、距离、点亮数量、发现 POI 和获得成就情况。

| 字段名 | 数据类型 | 是否核心字段 | 字段含义 |
| --- | --- | --- | --- |
| _id | String | 是 | 会话记录主键，由用户标识和会话标识组合生成 |
| user_id | String | 是 | 用户唯一标识，关联 `userinfo._id` |
| session_id | String | 是 | 单次探索会话标识 |
| start_time | String / DateTime | 是 | 本次探索开始时间 |
| end_time | String / DateTime | 是 | 本次探索结束时间 |
| duration_seconds | Number | 是 | 本次探索持续秒数 |
| duration_text | String | 否 | 持续时间的文本展示值，例如 `32s` |
| track_point_count | Number | 是 | 本次探索采集到的轨迹点数量 |
| distance_meters | Number | 是 | 本次探索估算距离，单位为米 |
| distance_text | String | 否 | 距离文本展示值，例如 `0 m` |
| session_unlocked_grid_count | Number | 是 | 本次会话中新点亮的网格数量 |
| unlocked_grid_count | Number | 是 | 本次会话统计的点亮网格数量 |
| total_unlocked_grid_count | Number | 是 | 截至本次会话结束后的累计点亮网格数量 |
| explore_ratio | Number | 是 | 截至本次会话结束后的探索比例 |
| coverage_ratio_text | String | 否 | 探索比例文本展示值 |
| discovered_poi_ids | Array | 否 | 本次会话发现的 POI 编号列表 |
| total_discovered_poi_ids | Array | 否 | 用户累计发现的 POI 编号列表 |
| completed_route_ids | Array | 否 | 本次会话完成的路线编号列表，当前为扩展预留 |
| total_completed_route_ids | Array | 否 | 用户累计完成的路线编号列表，当前为扩展预留 |
| earned_achievement_ids | Array | 否 | 本次会话获得的成就编号列表，当前为扩展预留 |
| total_earned_achievement_ids | Array | 否 | 用户累计获得的成就编号列表，当前为扩展预留 |
| updated_at | Date | 是 | 会话记录更新时间 |

主键规则：`_id = user_id + "_" + session_id`。  
更新方式：用户点击“结束探索”后写入或更新。  
业务作用：支持探索总结页、历史探索记录、累计进度计算和后续成就系统扩展。

### 4.3 gridstatus 网格点亮进度集合

`gridstatus` 是本项目“地图点亮”玩法的核心集合，用于记录某个用户已经点亮了哪些校园网格。每条记录表示一个用户对一个网格的点亮状态。

| 字段名 | 数据类型 | 是否核心字段 | 字段含义 |
| --- | --- | --- | --- |
| _id | String | 是 | 网格点亮记录主键，由用户标识和网格标识组合生成 |
| user_id | String | 是 | 用户唯一标识，关联 `userinfo._id` |
| grid_id | String | 是 | 校园探索网格编号，与前端 GeoJSON 网格要素编号对应 |
| unlock_time | String / DateTime | 是 | 用户首次点亮该网格的时间 |

主键规则：`_id = user_id + "_" + grid_id`。  
更新方式：用户轨迹与未点亮网格发生空间相交时自动生成。  
业务作用：用于判断网格是否已点亮、计算 `total_grids`、计算 `explore_ratio`，并支撑地图上的已探索/未探索状态渲染。

### 4.4 poi_records POI 点亮记录集合

`poi_records` 用于记录用户到达或触发过的校园兴趣点。当前 MVP 阶段主要用于验证“进入 POI 缓冲区后触发地标提示”的逻辑，后续可扩展为地标图鉴、校园知识卡片或任务系统。

| 字段名 | 数据类型 | 是否核心字段 | 字段含义 |
| --- | --- | --- | --- |
| _id | String | 是 | POI 触发记录主键，由用户标识和 POI 标识组合生成 |
| user_id | String | 是 | 用户唯一标识，关联 `userinfo._id` |
| poi_id | String | 是 | POI 唯一编号 |
| poi_name | String | 是 | POI 名称，例如“宝琛广场” |
| poi_type | String | 否 | POI 类型；当前样例中 `touch` 表示接近或触达触发 |
| trigger_time | String / DateTime | 是 | 用户触发该 POI 的时间 |
| updated_at | Date | 是 | 记录更新时间 |

主键规则：`_id = user_id + "_" + poi_id`。  
更新方式：用户当前位置进入 POI 缓冲区后自动生成或更新。  
业务作用：支持地标发现提示、地标打卡记录、后续图鉴收集和任务触发功能。

## 5. 集合关系说明

当前数据库的主要关系如下：

| 关系 | 说明 |
| --- | --- |
| `userinfo._id` 1:N `track_sessions.user_id` | 一个用户可以产生多次探索会话 |
| `userinfo._id` 1:N `gridstatus.user_id` | 一个用户可以点亮多个校园网格 |
| `userinfo._id` 1:N `poi_records.user_id` | 一个用户可以触发多个校园 POI |
| `gridstatus.grid_id` N:1 前端 GeoJSON 网格要素 | 点亮记录通过 `grid_id` 对应地图上的具体网格 |
| `poi_records.poi_id` N:1 前端 POI 数据 | POI 触发记录通过 `poi_id` 对应校园地标点 |
| `track_sessions.session_id` 1:N 会话内统计结果 | 一次探索会话汇总本次新增网格、POI、路线和成就等结果 |

可概括为：用户是核心主体；探索会话记录一次完整行为过程；网格点亮记录和 POI 触发记录保存具体空间事件；用户信息集合保存汇总后的总体进度。

## 6. 数据来源与生成方式

| 数据类别 | 数据来源 | 处理方式 | 当前落库情况 |
| --- | --- | --- | --- |
| 用户基础数据 | 微信小程序用户标识、用户授权信息 | 生成用户唯一标识，初始化探索统计字段 | 已建立 `userinfo` 集合 |
| 探索会话数据 | 用户点击开始/结束探索、定位轨迹统计结果 | 计算时长、距离、点亮数量、探索比例等摘要字段 | 已建立 `track_sessions` 集合 |
| 网格点亮数据 | 用户轨迹与校园网格的空间相交结果 | 通过网格 ID 保存用户点亮状态 | 已建立 `gridstatus` 集合 |
| POI 触发数据 | 用户位置进入 POI 缓冲区的判断结果 | 保存触发 POI、触发时间和 POI 类型 | 已建立 `poi_records` 集合 |
| 校园空间底图与网格 | 腾讯地图 API、校园公开资料、导览图、GIS 软件矢量化结果 | 后续整理为 GeoJSON，并作为前端业务图层叠加到底图上 | 当前主要以前端图层和编号关联形式使用 |

## 7. 数据格式说明

本次导出的 JSON 文件采用 CloudBase 常见的逐行 JSON 文档格式，每一行表示集合中的一条记录。时间字段存在两种形式：

| 时间格式 | 示例 | 说明 |
| --- | --- | --- |
| ISO 字符串 | `2026-05-13T12:14:18.102Z` | 主要用于业务事件时间，如开始时间、结束时间、触发时间 |
| CloudBase Date 对象 | `{"$date":"2026-05-13T12:18:28.526Z"}` | 主要用于云数据库导出的更新时间字段 |

字段命名以英文小写和下划线为主，便于前端代码、云函数和数据库查询统一调用。

## 8. 数据质量与约束说明

| 检查项 | 当前要求 |
| --- | --- |
| 用户唯一性 | `userinfo._id` 应保持唯一 |
| 会话唯一性 | `track_sessions._id` 应由 `user_id` 与 `session_id` 组合保证唯一 |
| 网格点亮唯一性 | 同一用户对同一 `grid_id` 只保留一条点亮记录，避免重复计数 |
| POI 触发唯一性 | 同一用户对同一 `poi_id` 可按当前 MVP 设计只保留一条记录，后续如需多次访问统计可增加访问次数或独立日志集合 |
| 关联完整性 | `track_sessions.user_id`、`gridstatus.user_id`、`poi_records.user_id` 应能在 `userinfo` 中找到对应用户 |
| 时间完整性 | 事件类记录应包含触发时间或更新时间，便于追踪探索过程 |
| 空间编号一致性 | `grid_id` 与前端 GeoJSON 网格编号保持一致；`poi_id` 与 POI 图层编号保持一致 |

## 9. 前期对象设计与当前集合对应关系

| 前期对象 | 当前落地方式 | 说明 |
| --- | --- | --- |
| USER 用户对象 | userinfo | 保存用户基础信息和累计探索进度 |
| GRID 网格单元对象 | 前端网格数据 + gridstatus | 网格基础空间数据在前端，点亮结果写入数据库 |
| TRACK 运动轨迹对象 | track_sessions | 当前 MVP 阶段保存探索会话摘要，不保存完整轨迹线 |
| EXPLORATION_RECORD 探索记录对象 | gridstatus | 记录用户点亮的具体网格及点亮时间 |
| CHECKPOINT 校史地标对象 | 前端 POI 数据 + poi_records | POI 基础信息在前端，用户触发记录写入数据库 |

## 10. 当前建库成果总结

当前项目已完成 MVP 阶段所需的核心数据库建设，建立了用户信息、探索会话、网格点亮记录和 POI 触发记录 4 个集合。数据库能够支撑用户探索行为记录、地图点亮进度保存、POI 触发记录保存和探索结算展示等核心功能。后续可在现有结构基础上继续扩展路线配置、成就配置、地标图鉴、排行榜和历史记录等功能。
